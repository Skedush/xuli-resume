二、核心工具详解

12.1 hermes-turn-log-plugin — 对话日志插件

定位：Hermes Plugin，把每一轮对话自动压缩成简短 Markdown 记录，重要内容写入 Obsidian 可检索笔记。

解决的问题：

  • 每次对话结束后不用手动整理笔记
  • 自动区分"重要可复用"和"临时一次性的内容"
  • 所有 turn 都能在 Daily 里回看，不丢历史

核心机制（5 个 hook）：

  • pre_llm_call：缓存本轮输入
  • transform_llm_output：调用 MiniMax 生成精简摘要，后台写 daily log；仅当被判定为 important 时才写 Obsidian Entry
  • on_session_start：初始化会话缓存并准备 vault 目录
  • on_session_end/finalize：只清理会话缓存，不重置 turn counter
  • on_session_reset：清理缓存并重置 turn counter

三层输出：

  1. Daily 日志：每轮都写，保留原始 user/assistant 输入，方便当天回看
  2. Obsidian Entry：仅 important turns，带 YAML frontmatter，可用 Dataview 检索
  3. Session Hub：每个 session 一页，串起该 session 的 Daily 和 Entry

依赖：MiniMax API Key + Obsidian vault 目录

踩过的坑：

  • API Key 需放在 ~/.hermes/plugin-configs/daily-turn-log.env，进程环境变量优先
  • gateway 上的对话是否能触发 hooks，取决于消息是否真正走到 LLM turn loop
  • 插件代码修改后需要重启 gateway 才能生效

12.2 my-agents-mcp — Workflow Helper MCP Server

定位：本地 stdio MCP 服务，为 remote codex-hermes workflow 提供工具函数、模板和校验。

解决的 问题：

  • Hermes 和 Codex/OpenCode 之间的 handoff 缺乏标准化
  • 不同 agent 之间没有统一的 artifact 骨架和质量门槛
  • workflow 文档分散且不易校验

6 个 MCP 工具：

工具 功能
get_workflow_guide 返回 Codex + Hermes workflow 简要指南
get_artifact_template 返回 AGENT_CONTEXT/CODEX_TASK/AGENT_RESULT 等模板
validate_artifact 校验工件是否包含必要章节和质量门槛

create_hermes_review_skeleton 返回 AGENT_REVIEW.md 骨架（含 APPROVED/NEEDS_CHANGES/BLOCKED）

调用方式（Hermes config.yaml）：

mcp_servers:
  my-agents-mcp:
    command: "node"
    args: ["/data/projects/repos/my-agents-mcp/src/server.js"]

核心设计：依赖自由（运行时无网络请求）+ 不默默编辑文件 + 治理三件套联动

治理三件套：

  • ~/.hermes/SOUL.md
  • /data/projects/_agent-workspace 工作流文档
  • /data/projects/repos/my-agents-mcp
  • 任一变更时需检查另外两个是否需要同步更新

四、踩坑汇总

4.1 网络相关

坑 解决方案
Docker Hub 网络超时/被 reset 配置镜像源
Hugging Face 网络不可达 离线启动时本地需有缓存
mihomo external-controller 绑定 0.0.0.0 改为 127.0.0.1 防暴露
Tailscale 与其他 VPN/代理冲突 关闭 exit node 或 subnet routes

4.2 Docker 相关

坑 解决方案
permission denied docker socket sudo usermod -aG docker $USER
healthcheck 用 curl 但容器无 curl 换 wget 或在镜像中装 curl
GPU 配置方式混淆 gpus: all 是 Docker Compose v5.1.4+ 语法
LiteLLM + Ollama 参数不兼容 drop_params: true + additional_drop_params

4.3 Shell / 终端相关

坑 解决方案
alias 和 function 同名导致 zshrc parse error unalias proxy_on 或换函数名
ed2k 链接特殊字符 | 被当管道 加单引号 'ed2k://...'
SSH 中文乱码 locale / 终端编码 / 客户端编码一致
su - ai 与 ssh ai@localhost 环境不同 注意 shell 初始化文件加载顺序

4.4 AI Agent 相关

坑 解决方案
sudo hermes 找不到命令 root PATH 与用户 PATH 不一致，用 hermes gateway install --system 需注意
agent 放 Docker 里复杂度剧增 agent 直接跑宿主机，Docker 只留给服务
本地模型 JSON 返回后无后续操作 放弃本地模型，用云端 API
8GB 显存文生视频/图生视频不行 ComfyUI 模型太大，需更高显存或云端
OpenCode 本地模型工具调用不稳定 依赖远程 API 更可靠

4.5 开发环境相关

坑 解决方案
Fcitx5 重启后输入法消失 环境变量放 ~/.xprofile 或 ~/.profile
bg-primary 移动端无效 用 bg-text-primary 或真实存在的 token
Navbar 移动端透明 移动端菜单背景用实底 + 足够 z-index
生产构建时 tsc 报错 tsc 类型检查与 vite build 需协调

4.6 远程操作相关

坑 解决方案
SSH sudo 需要交互式密码 生成脚本，用户本地 ssh -t host 'sudo bash script.sh' 执行
SSH 中文乱码 locale / 终端编码 / 客户端编码一致
远端 sudo -v 缓存不跨会话 每次需要 sudo 时重新认证
Docker 服务重启后需 grace period 等几秒再验证，不要立即判失败
