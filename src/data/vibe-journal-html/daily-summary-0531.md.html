2. PATH 修复（macOS 残留污染）

  • 症状：npm / hermes / codex 在某些 shell 入口下报 command not found
  • 根因：~/.profile 里残留 macOS 的 export PATH=...（含 /Users/ai/.local/bin、/Applications/iTerm.app/...、/System/Cryptexes/...），把 Linux 正常 PATH 覆盖
  • 修复：删除 macOS 残留 PATH；同时把 CARGO_HOME 从 /Users/ai/.cargo 改成 $HOME/.cargo
  • 验证：login bash / clean interactive bash / clean login zsh 三种入口下都能解析 hermes / codex / npm

3. daily-update-tools 定时任务 SyntaxError 排查与修复

  • 症状：5月29日、5月30日两天 04:00 跑失败（SyntaxError），5月31日成功
  • 根因：脚本里 python3 -c "..." 内联代码写了 import json, sys, argv —— argv 在 sys 模块里不能直接 import
  • 修复：
    -import json, sys, argv
+import json
+import sys
 data = json.load(sys.stdin)
-pkg = argv[1]
+pkg = sys.argv[1]
  • 为什么 5/31 成功：那天 npm ls -g 刚好输出空 {}，被 || echo '' 吞掉，Python 代码未实际执行
  • 验证：手动 systemctl --user start daily-update-tools.service，13:08 跑通

5. Hermes Dashboard 插件系统讲解

  • 插件目录：~/.hermes/plugins/<name>/
  • 组成：manifest.json + routes.py（FastAPI，可选） + dashboard/bundle.js（注入 Web 页面）
  • 关键设计：通过 window.__HERMES_PLUGIN_SDK__ 暴露 React / hooks / components / utils，插件不打包 UI 库
  • 与 Hermes Chat (TUI) 无关 —— 插件只在 hermes web 浏览器打开时加载
  • 典型用途：自定义监控卡片、一键部署按钮、第三方状态集成（PagerDuty/Grafana/Sentry）

6. Hermes 多 Profile vs delegate_task 工作流对比

  • 现状：mypc 只有 default profile，实际用 Hermes (leader) → delegate_task → Codex/OpenCode (worker)
  • Profiles 方案：进程级隔离，多 Hermes 实例并行（kanban 场景）
  • 关键差异：Profiles worker 只能用 Hermes；我的工作流 worker 用 Codex/OpenCode（specialized coder）
  • 结论：当前工作流更轻量，Profiles 反而是过度工程化
  • Profiles 正确用法：Profiles + Kanban → 多 Hermes 实例并行 → 每个 worker 内部自己决定是否调 Codex
