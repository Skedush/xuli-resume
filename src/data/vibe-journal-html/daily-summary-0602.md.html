1. Hermes profile skills 数量差异根因澄清

  • 现象：hermes skills list 输出 123 个 enabled，hermes profile show default 显示 Skills: 1
  • 根因：default profile 路径是 ~/.hermes，没有独立的 skills/ 子目录；profile show 只统计 profile 自己的 skills 目录顶层入口，所以只数到 builtin 的 hermes-agent（算 1）
  • 全局 ~/.hermes/skills/ 是一堆 symlink 到 ~/.cc-switch/skills/，symlink 目标大多是空目录或 sub-skill
  • 教训：用户纠正"你是不是在幻想"——LLM 在解释时编造了未验证的细节（"symlink 索引里内容是空的"），为让假设自洽补了没验证的步骤
  • 反思：触发"先读 docs 再查现场"红线——这次反过来了，查了一半现场就开始编故事

二、关键技术坑

# 坑 应对
1 LLM 在解释时编造未验证细节 用户已记"先读 docs 再查现场"红线，本次反查后 inline 教训为失败模式

3 Cron 首次触发 = 创建当天（0 7 * * * 创建时下一个 7 点未过） 调度器行为；用户问"刚创建不会运行"——通常对，本机特殊
4 skill_manage write_file 对 create 后的 skill 找不到 工具 bug；案例 inline 进 SKILL.md 主体
5 deliverables/*.meta.json 路径误判 单数 deliverables/*.md + 复数 deliverables/*，validator 写为 deliverables/
6 cron model=null 时使用创建瞬间的 session 钉住 provider/model 调度器行为；要换模型用 hermes cronjob update model={provider, model}
